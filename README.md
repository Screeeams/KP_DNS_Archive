# Курсовой проект: Формирование и анализ архива событий инфраструктуры



## 1. Сведения о студенте и варианте

- Студент: Серебряков А. Г.

- Группа: бТИИ-261

- Вариант: 12

- Моделируемая система: DNS-сервер



## 2. Формат входного сообщения

Сообщение представляет собой текстовую строку со следующими полями, разделенными пробелом:

час:минута node requests failures



Пример строки сообщения:

10:15 02 1500 12



## 3. Описание структуры Event

- h — часы (int, 0..23)

- m — минуты (int, 0..59)

- node — идентификатор узла DNS (int)

- requests — количество запросов (основной показатель, int)

- failures — количество зафиксированных сбоев (int)



## 4. Регламент архивации

Архивация буфера запускается при выполнении правила «хотя бы 2 из 3 условий»:

1\. Временной интервал: прошло не менее 60 минут с момента первого события в буфере;

2\. Количество сообщений: накоплено не менее 100 записей;

3\. Заполнение буфера: оперативный буфер заполнен не менее чем на 90%.



## 5. Критерий дубликата

Запись считается дубликатом, если одновременно выполняются условия:

1\. Совпадает идентификатор узла (node);

2\. Совпадает основной показатель (requests);

3\. Разница во времени поступления сообщений не превышает 10 минут.
